# Как будем разбирать проект

1. **Python и API.** Открой `pipeline/extract.py`: параметры периода → запрос SoQL
   → страницы → нормализация → независимая сверка → атомарная запись JSON.
   Запусти сначала один месяц. Объясни, почему пропущенная сумма не равна нулю.
2. **PostgreSQL.** Запусти `pipeline.load` без `--apply`: это SELECT-проверка.
   Затем загрузи один интервал. Повтори и проверь отсутствие дублей. Объясни,
   почему простого INSERT недостаточно и зачем нужна транзакция.
3. **dbt.** Пройди от source до staging и двух marts. Запусти `dbt build`.
   Изучи тест `reconcile_mart.sql`: возвращённая строка означает провал проверки.
4. **Airflow.** Прочитай DAG, запусти вручную один месяц, изучи логи и retries.
   Убедись, что ошибка проверки блокирует экспорт. Включать расписание стоит после
   успешного ручного запуска всей цепочки.
5. **n8n.** Импортируй `n8n/quality_event.json`. Это отдельное необязательное
   упражнение: принять и проверить событие успешного пайплайна. Внешние сообщения
   не отправляются. Опубликуй/активируй workflow и настрой внутренний webhook URL
   `http://n8n:5678/webhook/revenue-quality` в окружении Airflow.
6. **Streamlit.** Запусти `dashboard/app.py`, изучи три страницы и фильтры. Сначала
   доступен явно помеченный API preview; итоговая версия читает экспорт после dbt.
7. **GitHub.** Опубликуй только эту папку как отдельный репозиторий. Добавь диаграмму,
   скриншоты, результаты проверок и реальную ссылку на Streamlit. Подготовь объяснение
   решений: grain, revisions, идемпотентность, контроль качества, границы метрик.

Перед собеседованием важно уметь самостоятельно запустить, изменить и восстановить
этот проект. Pet-проект показывает инженерную практику, но не заменяет коммерческий
опыт эксплуатации production ETL.
